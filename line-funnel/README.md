# LINE 自動配信システム（総合型選抜・学校推薦型選抜 来場者向け）

会場セミナー・ブース相談の来場者に LINE 公式アカウントへ登録してもらい、
フロントエンド商品（1万円以内）からバックエンド商品（個別相談 → 10万〜40万円）へ自動で案内する仕組みです。

固定費ゼロの構成：LINE Messaging API（無料プラン）＋ Cloudflare Workers / D1（無料枠）＋ Stripe（決済ごとの手数料のみ）

初めて動かすときの準備（アカウント作成・トークン発行・Webhook設定）は **[docs/SETUP.md](docs/SETUP.md)** を上から順に進めてください。

## 配信シナリオ

| いつ | 誰に | 内容 | 送り方 |
|---|---|---|---|
| 友だち追加の直後 | 全員 | プレゼント① | 応答メッセージ（**通数に数えない**） |
| 登録7日後 | 全員 | プレゼント② | 定期処理 |
| 登録14日後 | フロント未購入者 | フロント商品の案内（本人専用の Stripe 決済リンク＋銀行振込の案内） | 定期処理 |
| 購入を検知した直後 | 購入者 | お礼（設定で止められる） | Stripe Webhook |
| 登録21日後 | フロント購入者 | バックエンド商品の個別相談案内（21日目より後に購入した人には購入後の定期処理で送る） | 定期処理 |
| 14日目から30日ごと | フロント未購入者 | 月1回のお役立ち情報（順番に送り、最後まで行ったら先頭に戻る） | 定期処理 |

- 日数は日本時間の日付で数えます（登録日 = 0日目）。
- 1人に送るのは1日1通までです。期限を過ぎた配信が複数ある場合は早いものから1日1つずつ送ります。
- ブロックした人には送りません。ブロック解除（再追加）した人は、最初の登録日のまま続きから配信します。

## 配信文・リンクの差し替え

**`src/scenario-config.js` だけを編集**し、`npx wrangler deploy` で反映します（登録者のデータは消えません）。

- `links` … プレゼント①②の URL、Stripe の決済リンク、個別相談の予約ページ
- `frontProduct` … 商品名・価格の表記・銀行振込の案内文
- `schedule` … 配信日（7日・14日・21日・30日間隔）
- `scenario` … 各配信の文面。`{{paymentUrl}}`（本人専用の決済リンク）、`{{refCode}}`（申込番号）などを差し込めます

## 購入の検知

- **Stripe**：決済リンクに LINE のユーザーIDを `client_reference_id` として付けて送るので、決済が完了すると
  Stripe Webhook で誰が買ったかが自動でわかり、購入フラグが立ってシナリオが購入者用に切り替わります。
  コンビニ払いなどの後払いは、入金完了の時点で購入として扱います。
- **銀行振込**：フロント案内に申込番号（6文字）が入っています。振込名義に入れてもらい、入金を確認したら次のコマンドで登録します。

```bash
curl -X POST https://<あなたのWorkerのURL>/admin/purchase -H "Authorization: Bearer <ADMIN_TOKEN>" -H "Content-Type: application/json" -d '{"refCode":"ABC234"}'
```

## 管理用の URL（すべて `Authorization: Bearer <ADMIN_TOKEN>` が必要）

| URL | 内容 |
|---|---|
| `GET /admin/stats` | 登録者数・ブロック数・購入者数（Stripe/振込別）・配信ごとの送信数 |
| `POST /admin/purchase` | 銀行振込などの購入を登録（`{"refCode":"..."}` または `{"userId":"U..."}`） |
| `POST /admin/run-daily` | 定期処理をすぐに実行（動作確認用） |

## 保存しているデータ（Cloudflare D1）

- `users` … LINE ユーザーID、表示名、申込番号、登録日、フロント購入の有無、購入日、購入方法、状態（有効/ブロック）
- `deliveries` … 誰にどの配信をいつ送ったか（配信状況）
- `stripe_events` … Stripe Webhook の重複受信防止

## 無料枠についての注意

- **LINE の無料プランは月200通まで**。応答メッセージ（登録直後のプレゼント①）は数えられませんが、
  それ以外は1人1通ずつ数えられます。上限に達するとその月の配信は止まり、翌月（または有料プランに切り替え後）の定期処理で続きから送ります。
  目安として、登録者1人あたり最初の1か月でプレゼント②・フロント案内・お役立ち情報などの3通前後を使うので、月の新規登録が60〜70人を超えるなら有料プランを検討してください。
- **Cloudflare Workers の無料プラン**は、1回の実行で外部へのリクエストが50件までです。
  同じ文面の配信はまとめて送ります（1リクエストで最大500人）が、決済リンク入りのフロント案内は1人ずつ送るため、
  定期処理は毎日 JST 10:00〜11:50 に10分おき（1回40件まで）に実行して送り切ります。それでも足りない規模になったら、Workers の有料プラン（月5ドル）を検討してください。
- **秘密情報**（LINE のチャネルシークレット・アクセストークン、Stripe の Webhook シークレット、管理用トークン）はコードに書かず、
  `npx wrangler secret put` で Cloudflare に登録します。

## ファイル構成

```
src/scenario-config.js  配信文・リンク・配信日（ここを編集する）
src/index.js            Webhook と管理用 URL の受け口、定期処理の入口
src/scenario.js         経過日数から今日送る配信を決める
src/daily.js            定期処理（まとめて送信・上限の管理）
src/db.js               D1 へのデータ保存
src/line.js             LINE Messaging API
src/crypto.js           LINE / Stripe の署名検証
migrations/             D1 のテーブル定義
test/                   自動テスト（npm test）
docs/SETUP.md           初回の準備手順
```
